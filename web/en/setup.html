Setup and FAQ

S-01

Self-hosting: construction sequence

You need Docker and somewhere to run 24/7
work through the steps in order

Fastest way on a Raspberry Pi or a Debian machine: one command. The script installs Docker and git, asks for the bot token and application ID, generates the passwords, starts the bot and registers the slash commands. Optionally it also installs the backup and auto-update timers, and with --tft it sets up the 3.5-inch TFT screen too. It is safe to run again, and --dry-run only previews what it would do.

curl -fsSL https://raw.githubusercontent.com/nhaajtt/musiDISCORD/main/scripts/install-pi.sh | sh

To preview, add -s -- --dry-run after sh. If you want to control each step, or you are on another machine, follow the manual steps below.

The manual way, step by step:

  1. Get the token and Application ID

    Open the Discord Developer Portal, create an application and add a Bot. The token is on the Bot tab and the Application ID is under General Information. The bot only uses slash commands, buttons and voice channels, so it needs no privileged intents.

  2. Create the .env file

    Copy the sample file and fill in DISCORD_TOKEN and CLIENT_ID. Also set LAVALINK_PASSWORD; add CONTRIBUTIONS=on if you want to accept file contributions; add Spotify keys if you want to paste Spotify links.

    cp .env.example .env

    Online lyrics lookup through LRCLIB is optional and you can turn it on or off in the configuration; see .env.example for the variable names.

  3. Build the bot and Lavalink

    One command builds both. On first run Lavalink downloads its plugins, which takes about a minute, and the bot keeps retrying the connection while it waits. Docker health-checks each service; look with docker compose ps.

    docker compose up -d --build

  4. Register the slash commands

    Run it once, and again whenever you add or change commands (version 2.4 added /playlist and /radio). Set GUILD_ID in .env if you want the commands to appear instantly in one server while testing.

    docker compose run --rm bot node src/deploy-commands.js

  5. Invite the bot and add music

    Invite the bot with the link at the top of the page (change client_id to your own ID and keep the permissions=281474979908608 part). Drop music files into the music/ folder, and put a .lrc file next to a song if it has lyrics; new files do not need a bot restart.

    Settings, the queue, stats, playlists and favorites are stored in the data/ folder next to docker-compose.yml. Keep this folder so nothing is lost when you rebuild the containers.

S-02

General notes

Questions people often ask
before inviting the bot

Is YouTube reliable?

The bot can play links and song names from YouTube, but YouTube keeps changing how it blocks music players, so some songs occasionally fail to play. When that happens, try SoundCloud, a Spotify link, or your own music files.

What permissions does the bot need?

The invite link asks for seven permissions: View Channel, Send Messages, Embed Links, Attach Files, Connect, Speak and Set Voice Channel Status. Send Messages, Embed Links and Attach Files are used for the Now Playing card and the /wrapped image; Set Voice Channel Status is used for the "Now playing" line on the channel. The bot does not read anyone's message content.

How do I limit who can control the music?

An admin runs /settings dj-role and picks a role. From then on only that role (and people with Manage Server) can use the control commands and buttons. Leave the role empty and anyone can.

Can it play my own music files?

Yes, if you host the bot yourself: put files in the music folder, the bot reads their tags to build a library, and then you use /local, /album, /artist or /nhaajt. A bot hosted by someone else can only play the music in that person's folder. You are responsible for having the right to use those music files.

Does the music quiz need permission to read messages?

No. Players press an answer button and type their guess in a small pop-up window, so the bot never needs to read the chat channel. Questions come from the server's own music library.

Where do the lyrics come from?

From a .lrc file next to the music file, or lyrics embedded in the file's tags. If neither exists, the bot can look them up online at LRCLIB, which sends the song title, artist and duration to that service. The host can turn this feature off.

Does the bot download music from YouTube?

No. The bot downloads nothing from YouTube, Spotify or SoundCloud into the library. With /request it only records a name or link on a wish list and never opens the link. Only valid files are added to the library.

How do I add songs to the library?

Submit your own file through /contribute (tick the box confirming you own it or may share it, and the bot owner will review it) or suggest a song with /request. Contributions are off by default: the bot owner must set CONTRIBUTIONS=on and a server admin must turn on /settings contributions.

What does the bot remember about the server and about me?

Server settings, the saved queue and, since version 2.0, listening history, ratings, favorites, quiz scores and badges, keyed by Discord ID. Since version 2.4 it also keeps playlists; everything lives in the data/ folder on the machine running the bot. Since version 2.1 it also keeps your contribution and request profile. You can stop stats being recorded with /privacy stats and delete your data, personal playlists included, with /privacy delete. Details are on the Privacy page.

How do I run several Lavalink nodes?

List them in .env with LAVALINK_NODES, for example main=lavalink:2333,backup=lavalink2:2333, then start the second node with docker compose --profile ha up -d. When one node goes down, its players move to another. Every node must see the same music folder. /stats shows how many nodes are up.

When do I need sharding?

Sharding is optional: set SHARDS=auto or a number. All shards run in the same process, and one shard is enough up to 2,500 servers. /stats shows the shard count.

Does the bot leave the channel by itself?

Yes. By default, when the channel empties or the songs run out, the bot leaves after 60 seconds. With /247 on it stays even when nobody is there and after a restart. /nhaajt mode never runs out of songs, so the bot stays until the channel empties or you type /stop.
