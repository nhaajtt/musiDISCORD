S-02

Các phần nói chuyện với nhau thế nào

Bot chỉ ra lệnh
Lavalink lo âm thanh

Discord  <-->  bot (Node.js)  <-->  Lavalink  <--  thư mục music/
                |
                +-- data/        SQLite và JSON (cài đặt, thống kê, hàng chờ)
                +-- API :8787    chỉ mở ở 127.0.0.1, có token
                |      +-- Tailscale serve  -->  điện thoại, máy tính
                |      +-- display.py       -->  màn TFT (framebuffer, cảm ứng)

Bot không phát âm thanh trực tiếp: nó ra lệnh cho Lavalink, Lavalink giải mã file trong music/ và gửi vào kênh thoại. Tách như vậy để bot nhẹ, còn phần nặng nằm riêng và khởi động lại độc lập.

S-03

Triển khai từng bước

Từ chiếc Pi trắng
tới bot chạy 24/7

Cách nhanh nhất: một lệnh. Script cài Docker và git, hỏi token và Application ID của bot, tự sinh các mật khẩu, khởi động bot và đăng ký lệnh gạch chéo. Tùy chọn, nó cài thêm timer sao lưu và tự cập nhật, và với --tft thì cài đặt luôn màn TFT 3.5 inch. Chạy lại được mà không hỏng gì; thêm --dry-run để chỉ xem trước. Chạy trên Raspberry Pi hoặc máy Debian.

curl -fsSL https://raw.githubusercontent.com/nhaajtt/musiDISCORD/main/scripts/install-pi.sh | sh

Ví dụ xem trước: thêm -s -- --dry-run sau sh. Các bước thủ công bên dưới là cách làm tay, cho ai muốn tự kiểm soát từng việc.

Cách thủ công, từng bước:

  1. SSH bằng khoá, không dùng mật khẩu

    Tạo khoá trên máy chính rồi chép sang Pi. Lưu ý: nếu đặt passphrase thì chế độ không tương tác sẽ im lặng bị từ chối, nên khoá dùng cho tự động hoá không đặt passphrase.

    ssh-keygen -t ed25519
ssh-copy-id nhaajt@<địa chỉ Pi>

  2. Cài Docker và quyền

    Cài Docker và Compose v2, thêm tài khoản vào nhóm docker để không cần sudo mỗi lần. Việc nào cần quyền root thì tôi tự chạy riêng.

    sudo apt install -y docker.io git
sudo usermod -aG docker $USER

  3. Lấy mã, nhạc, cấu hình

    Clone repo, chép thư mục music/ và file .env (chứa token, không nằm trong git). Plugin Lavalink là file Java nên chép thẳng từ máy chính nếu máy chủ Maven không có.

    git clone https://github.com/nhaajtt/musiDISCORD.git

  4. Dựng và chạy

    Một lệnh dựng cả ba container. Bot chỉ khởi động sau khi Lavalink báo khoẻ, nhờ depends_on kèm healthcheck.

    docker compose up -d --build

  5. Truy cập từ xa bằng Tailscale

    Cài Tailscale, bật dịch vụ tự chạy khi khởi động (bước tôi từng quên), rồi dùng serve để có địa chỉ HTTPS riêng tư cho trang trạng thái và Kuma.

    sudo systemctl enable --now tailscaled
tailscale serve --bg --https=443 http://127.0.0.1:8787

  6. Lịch chạy và màn hình

    Thêm dòng cron cho sao lưu, tự cập nhật, và @reboot để bật màn TFT khi Pi khởi động.

S-04

Giữ cho nó sống

Chạy được chưa đủ
phải tự phục hồi được

Các việc vận hành tự động
ViệcCách làm
Sao lưuMỗi ngày 4:30. Dùng VACUUM INTO để có bản sao SQLite nhất quán dù bot đang ghi, nén lại, giữ 14 bản, tuỳ chọn đẩy lên cloud bằng rclone.
Tự cập nhậtMỗi ngày 5:00: lấy commit mới, chỉ chấp nhận fast-forward, dựng lại, chờ bot khoẻ; nếu hỏng thì quay về bản trước và báo qua Discord.
Giám sátUptime Kuma kiểm tra bot và Lavalink, báo về kênh Discord qua webhook.
Truy cập từ xaTailscale kèm serve: địa chỉ HTTPS chỉ thiết bị trong tài khoản mới vào được.
Giảm mòn thẻ SDTín hiệu "còn sống" ghi vào RAM, tắt lưu hàng chờ định kỳ, log Docker xoay vòng.
Nhiều node LavalinkKhai báo LAVALINK_NODES (ví dụ main=lavalink:2333,backup=lavalink2:2333) rồi chạy docker compose --profile ha up -d cho node thứ hai. Một node ngừng thì các trình phát chuyển sang node khác. Mọi node phải thấy cùng một thư mục nhạc; /stats hiện số node đang chạy.
Chia shardTùy chọn, SHARDS=auto hoặc một con số; mọi shard chạy trong một tiến trình. Một shard là đủ tới 2.500 server.
Tự khởi động lạiChính sách restart của Docker, các dịch vụ hệ thống đã enable, @reboot cho màn TFT.
S-05

Màn hình cắm trên chân GPIO

Phần khó nhất của dự án
câu chuyện đầy đủ nằm trong nhật ký

Màn TFT 3.5 inch cảm ứng điện trở hiện bài đang phát: tên bài cỡ lớn, nghệ sĩ, thanh tiến trình, các nút điều khiển bằng bút và ảnh đại diện của tôi tràn mép như bìa tạp chí. Chương trình display.py đọc API trạng thái của bot rồi vẽ thẳng lên framebuffer, đọc cảm ứng qua evdev.

Điều tôi học nhiều nhất là cách chia nhỏ vấn đề phần cứng thành giả thuyết kiểm chứng được, thay vì thử bừa:

S-06

Trang trạng thái cho điện thoại và màn lớn

Cùng dữ liệu
hai giao diện

Bot có một API trạng thái nhỏ và một trang /display: chiếc đĩa quay và đập theo BPM thật của bài (do bot tự đo), màu cả trang đổi theo bài, thước dưới chân là các vạch nhịp để chạm tua. Trang chạy trên điện thoại, máy tính bảng hoặc màn hình lớn.

  • Chỉ mở ở 127.0.0.1 trên máy chạy bot; ra ngoài bằng Tailscale.
  • Điều khiển cần DISPLAY_TOKEN; không có token thì chỉ xem được.
  • Không lộ ID Discord hay tên người yêu cầu; tự ẩn khi đang đố nhạc.
  • Chính sách CSP chặt: không script nhúng, không tài nguyên ngoài.
