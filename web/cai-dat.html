Cài đặt và hỏi đáp

S-01

Tự host: trình tự thi công

Cần Docker và một chỗ chạy 24/7
làm lần lượt từ bước 1

Cách nhanh nhất trên Raspberry Pi hoặc máy Debian: một lệnh. Script cài Docker và git, hỏi token và Application ID của bot, tự sinh các mật khẩu, khởi động bot và đăng ký lệnh gạch chéo. Tùy chọn, nó cài thêm timer sao lưu và tự cập nhật, và với --tft thì cài đặt luôn màn TFT 3.5 inch. Chạy lại được mà không hỏng gì; thêm --dry-run để chỉ xem trước nó sẽ làm gì.

curl -fsSL https://raw.githubusercontent.com/nhaajtt/musiDISCORD/main/scripts/install-pi.sh | sh

Ví dụ xem trước: thêm -s -- --dry-run sau sh. Muốn tự kiểm soát từng bước, hoặc chạy trên máy khác, làm theo các bước thủ công bên dưới.

Cách thủ công, từng bước:

  1. Lấy Token và Application ID

    Vào Developer Portal của Discord, tạo application, thêm Bot. Token nằm ở tab Bot, Application ID nằm ở General Information. Bot chỉ dùng lệnh gạch chéo, nút bấm và kênh thoại nên không cần intent đặc quyền.

  2. Tạo file .env

    Sao chép file mẫu rồi điền DISCORD_TOKEN và CLIENT_ID. Đặt thêm LAVALINK_PASSWORD; muốn nhận file đóng góp thì thêm CONTRIBUTIONS=on; điền khóa Spotify nếu muốn dán link Spotify.

    cp .env.example .env

    Tra lời bài hát online qua LRCLIB là tùy chọn, bạn bật hoặc tắt trong cấu hình; xem file .env.example để biết tên biến.

  3. Dựng bot và Lavalink

    Một lệnh dựng cả hai. Lần đầu Lavalink tải plugin nên mất khoảng một phút, bot sẽ tự thử kết nối lại trong lúc chờ. Docker tự kiểm tra sức khỏe của từng dịch vụ, xem bằng docker compose ps.

    docker compose up -d --build

  4. Đăng ký lệnh gạch chéo

    Chạy một lần, và chạy lại mỗi khi thêm hoặc đổi lệnh (bản 2.4 thêm /playlist và /radio). Điền GUILD_ID trong .env nếu muốn lệnh hiện ngay ở một server khi thử.

    docker compose run --rm bot node src/deploy-commands.js

  5. Mời bot và thêm nhạc

    Mời bot bằng link ở đầu trang (đổi client_id thành ID của bạn, giữ nguyên phần permissions=281474979908608). Bỏ file nhạc vào thư mục music/, đặt file .lrc cạnh file nhạc nếu có lời; thêm file mới không cần khởi động lại bot.

    Cài đặt, hàng chờ, thống kê, playlist và danh sách yêu thích lưu trong thư mục data/ cạnh docker-compose.yml, giữ thư mục này để không mất khi dựng lại container.

S-02

Ghi chú chung

Những câu hay được hỏi
trước khi mời bot

YouTube có ổn định không?

Bot phát được link và tên bài từ YouTube, nhưng YouTube hay đổi cách chặn công cụ phát nhạc nên có lúc một số bài không phát được. Gặp bài lỗi, thử nguồn SoundCloud, link Spotify hoặc file nhạc của bạn.

Bot cần những quyền gì?

Link mời xin bảy quyền: Xem kênh (View Channel), Gửi tin nhắn (Send Messages), Nhúng liên kết (Embed Links), Đính kèm file (Attach Files), Kết nối (Connect), Nói (Speak) và Đặt trạng thái kênh thoại (Set Voice Channel Status). Gửi tin nhắn, Nhúng liên kết và Đính kèm file dùng cho thẻ Đang phát và ảnh /wrapped; Đặt trạng thái kênh thoại dùng cho dòng "Đang phát" trên kênh. Bot không đọc nội dung tin nhắn của ai.

Làm sao giới hạn ai được điều khiển nhạc?

Quản trị viên gõ /settings dj-role và chọn một role. Từ đó chỉ role đó (và người có quyền Manage Server) dùng được các lệnh và nút điều khiển. Bỏ trống role thì ai cũng dùng được.

Phát file nhạc của tôi được không?

Được, nếu bạn tự host bot: bỏ file vào thư mục music, bot đọc thẻ để dựng thư viện rồi bạn dùng /local, /album, /artist hoặc /nhaajt. Bản bot mà người khác host thì chỉ phát được nhạc nằm trong thư mục của họ. Bạn tự chịu trách nhiệm về việc có quyền dùng các file nhạc đó.

Đố nhạc có cần quyền đọc tin nhắn không?

Không. Người chơi bấm nút trả lời rồi gõ đáp án trong một cửa sổ nhỏ, nên bot không cần đọc nội dung kênh chat. Bài thi lấy từ thư viện nhạc của chính server.

Lời bài hát lấy từ đâu?

Từ file .lrc cạnh file nhạc, hoặc lời nhúng trong thẻ của file. Nếu không có, bot có thể tra online ở LRCLIB và việc đó gửi tên bài, nghệ sĩ, thời lượng tới dịch vụ ấy. Người host tắt được tính năng này.

Bot có tải nhạc từ YouTube về không?

Không. Bot không tải gì từ YouTube, Spotify hay SoundCloud về kho. Với /request, bot chỉ ghi tên hoặc link vào danh sách mong muốn và không mở link đó. Chỉ file hợp lệ được đưa vào kho.

Làm sao thêm bài vào kho nhạc?

Gửi file của bạn qua /contribute (tick xác nhận bạn sở hữu hoặc được phép chia sẻ, chủ bot sẽ duyệt) hoặc đề xuất bằng /request. Tính năng đóng góp tắt sẵn, cần chủ bot bật CONTRIBUTIONS=on và quản trị server bật /settings contributions.

Bot nhớ gì về server và về tôi?

Cài đặt của server, hàng chờ đã lưu, và từ bản 2.0 có thêm lịch sử nghe, đánh giá, yêu thích, điểm đố nhạc và huy hiệu theo ID Discord. Từ bản 2.4 có thêm playlist; tất cả nằm trong thư mục data/ trên máy chạy bot. Từ bản 2.1 còn có hồ sơ đóng góp và đề xuất của bạn. Bạn tắt việc ghi thống kê bằng /privacy stats và xóa dữ liệu của mình, gồm cả playlist cá nhân, bằng /privacy delete. Chi tiết ở trang Quyền riêng tư.

Chạy nhiều node Lavalink thế nào?

Khai báo trong .env bằng LAVALINK_NODES, ví dụ main=lavalink:2333,backup=lavalink2:2333, rồi bật node thứ hai bằng docker compose --profile ha up -d. Khi một node ngừng, các trình phát được chuyển sang node khác. Mọi node phải thấy cùng một thư mục nhạc. /stats hiện số node đang chạy.

Khi nào cần chia shard?

Chia shard là tùy chọn: đặt SHARDS=auto hoặc một con số. Mọi shard chạy trong cùng một tiến trình, và một shard là đủ cho tới 2.500 server. /stats hiện số shard.

Bot có tự rời kênh không?

Có, mặc định kênh không còn ai, hoặc hết bài, bot rời sau 60 giây. Bật /247 on thì bot ở lại kể cả khi vắng người và sau khi khởi động lại. Chế độ /nhaajt thì không hết bài nên bot ở lại tới khi kênh trống hoặc bạn gõ /stop.

Muốn thêm vài con bot nhỏ tán gẫu cho server bớt vắng? Chúng là một dự án riêng, chạy chung Pi được.
